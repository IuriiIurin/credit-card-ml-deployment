# Архитектура сервиса

## Схема взаимодействия

Клиент -> Flask API -> Модель -> Flask API -> Клиент

## Монолитный подход для веб-сервиса

В данном проекте выбран монолитный подход. Flask приложение объединяет загрузку модели и обработку запросов в одном сервисе.
- Проект небольшой: одна модель, два эндпоинта, общие ресурсы
- Проще в разработке, тестировании и развертывании
- Нет необходимости в масштабировании отдельных компонентов

## Эндпоинты

- GET /health - проверка работоспособности сервиса, возвращает {"status": "OK"}, возвращает статус 200
- POST /predict - принимает JSON с признаками клиента, возвращает предсказание
- При невалидном JSON возвращается ошибка 400 с описанием проблемы

## Загрузка модели

Модель загружается один раз при старте приложения через model_handler.py и используется как singleton - один объект на всё время
работы сервиса. Сервис stateless - не хранит состояние между запросами, каждый запрос обрабатывается независимо.

## Формат запроса и ответа

Запрос (POST /predict):
{"LIMIT_BAL": 20000, "SEX": 2, "EDUCATION": 2, ...}

Ответ:
{"prediction": 0, "probability": 0.23, "model_version": "v1"}

## Docker

Сервис упакован в Docker контейнер на базе python:3.12-slim.
Контейнер запускается на порту 5000.
Образ доступен на Docker Hub: iuriiiurin/credit-card-ml

## Концепт брокера сообщений (RabbitMQ)

При масштабировании можно добавить RabbitMQ для:
- Асинхронной обработки батч-предсказаний
- Логирования запросов и ответов
- Распределения запросов между несколькими копиями сервиса

## Логирование

Запросы и ответы API логируются в формате JSON.
В production логи собирались бы через ELK-стек (Elasticsearch, Logstash, Kibana).

## Концепты MLOps

### DVC (Data Version Control)
Инструмент для версионирования данных и моделей, аналог Git для файлов данных.
В контексте данного проекта DVC мог бы использоваться для:
- Версионирования датасета UCI Credit Card
- Отслеживания изменений в model_v1.pkl и model_v2.pkl
- Воспроизводимости пайплайна обучения через dvc.yaml

### MLflow
Инструмент для отслеживания экспериментов и управления моделями.
В контексте данного проекта MLflow мог бы использоваться для:
- Логирования метрик обучения (F1, Recall, Precision) для v1 и v2
- Сравнения экспериментов с разными гиперпараметрами
- Хранения артефактов моделей в Model Registry

### ONNX
Формат для переносимости моделей между фреймворками.
Модель можно конвертировать в ONNX для:
- Ускорения инференса через ONNX Runtime
- Переноса модели в среды без scikit-learn
- Оптимизации под конкретное железо (CPU/GPU)

Пример конвертации:
from skl2onnx import convert_sklearn
onnx_model = convert_sklearn(pipeline, "credit_card_default", initial_types)
